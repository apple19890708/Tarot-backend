# 維護版本計畫書

`doc/` 底下每個版本一份計畫書（`v01` 起算），是這個專案的決策紀錄。**規則有變更就要同步更新**，否則下次改規則的人會依據過期的決議。

## 更新既有計畫書

1. 先找出這條規則屬於哪一版（規則 1～6 在 `v01`、規則 7～10 在 `v02`，其餘看檔名）。
2. 同步三個地方：**規格章節**、**決議紀錄**、**狀態／進度表**（頁首的「狀態：」那行也要改）。
3. 改了門檻就寫清楚新舊值與理由，並指向 `src/data/ruleConfig.js` 的 key。

## 新開一份計畫書

檔名 `vXX-<主題>-plan.md`，接續最大的版號。骨架：

```markdown
# vXX　<標題>

建立日期：YYYY-MM-DD
狀態：規劃中

## 一、目標
要解決什麼問題；**不做的事**（明確劃掉範圍，避免膨脹）

## 二、規格
規則／API／資料結構

## 三、階段與進度
| 階段 | 內容 | 狀態 |

## 四、決議紀錄
日期 ＋ 決定 ＋ 理由
```

## 要點

- 繁體中文，文字描述決策，不要貼大段程式碼。
- 「不做的事」一定要寫，這是本專案控制範圍的方式。
- 計畫書完成後，在 `doc/worklog.md` 留一行指向它。
