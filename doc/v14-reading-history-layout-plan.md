# v14　我的占卜紀錄：兩欄式版面

建立日期：2026-10-27
狀態：階段 1～4 已實作（2026-10-27），階段 5 待實際檢視畫面

v13 完成了紀錄的保存與回顧，前端 `/history` 目前是「單欄列表＋點開展開」。
這一版只調整前端的閱讀方式，後端 API 沿用 v13，不需要改。

## 一、目標

把「我的占卜紀錄」改成兩欄：

- **左欄：可收合的檢索標籤**：列出使用者所有的占卜紀錄，每筆是一個可點選的標籤，
  可以用關鍵字與篩選條件縮小範圍
- **右欄：內容**：顯示左欄選中那一筆的完整回顧（牌、牌義、組合分析、AI 解讀）
- 左欄收合後，右欄佔滿寬度，方便專心閱讀長篇分析
- 換一筆來看時不必往回捲、不必收合上一筆

目前的問題：展開一筆後內容很長，要看下一筆得捲回列表；同時只能看一筆，卻要在同一欄裡來回切換。

**不做的事**（這一版不碰）：

- 後端修改（新 API、伺服器端搜尋、新欄位）
- 使用者自訂標籤、收藏、置頂
- 兩筆紀錄並排比較
- 多選、批次刪除
- 紀錄之間的趨勢統計
- 匯出（仍留在 v13 階段 5）
- 拖曳調整左欄寬度

## 二、規格

### 版面

| 寬度 | 左欄 | 右欄 |
|---|---|---|
| 桌機（`lg` 以上） | 固定寬度約 20rem，隨頁面黏住（sticky），自己捲動 | 剩餘寬度 |
| 桌機，左欄收合 | 縮成一條窄欄，只留「展開」按鈕與筆數 | 佔滿寬度 |
| 手機與平板（`lg` 以下），清單收合 | 不佔版面，內容區上方只留「開啟紀錄清單」按鈕 | 佔滿寬度 |
| 手機與平板（`lg` 以下），清單展開 | **滿版**蓋在內容上方，右上角有關閉按鈕 | 被清單蓋住 |

- 手機上點選一筆後，清單自動收合，直接顯示所選紀錄的內容。
- 手機上清單滿版展開時，背景頁面不跟著捲動；按關閉或選了一筆就收合。
- 桌機的收合狀態記在 `localStorage`，只是個人偏好，讀不到時預設展開。
  手機不記，每次進頁面都依「預設選取」的規則決定（見右欄）。
- 樣式沿用深色玻璃（`bg-white/5`、`border-white/10`、`rounded-[1.75rem]`），選中的標籤用 amber 邊框標示，
  與現有的展開狀態一致。

### 左欄：檢索標籤

- **資料來源**：每人上限 100 筆，摘要很小，所以進頁面時用 `GET /api/readings`（每頁 50）載入**全部**摘要，
  最多兩次請求。左欄不分頁；篩選在前端做，結果才完整。
- **每個標籤只顯示**：日期（短格式）、問題（最多兩行，超過截斷；未填寫顯示「未填寫問題」）。
  牌陣、張數、牌名、AI 解讀與否都留到右欄看，左欄保持精簡。
- **分組**：依年月分組（例如「2026 年 10 月」），最新的在最上面。
- **檢索**：
  - 關鍵字：比對問題文字與牌名快照（`cards[].nameZh`）
  - 篩選：「全部」／「有 AI 解讀」
  - 顯示「符合 N 筆／共 M 筆」；沒有符合的時候提示並提供「清除條件」
- 標籤是按鈕，選中的那一筆加上 `aria-current`；鍵盤可以用 Tab 逐一選取。

### 右欄：內容

- 詳情一樣點選後才向 `GET /api/readings/:id` 載入（分析由後端重算），沿用 `StepResult`（`hideFlowActions`）。
- 上方顯示日期、問題，以及刪除按鈕（沿用二段式「確定刪除？」）。
- **預設選取**：進頁面時自動選最新一筆（網址有 `?id=` 時以網址為準）。手機上清單一開始是收合的，
  直接看到內容；沒有任何紀錄時改顯示下面的「立即占卜」引導。
- **沒有任何紀錄**（從沒保存過，或全部刪完）：
  - 右欄顯示引導：一句說明（占卜後在結果頁按「保存紀錄」就會出現在這裡）＋「立即占卜」按鈕，
    用 `RouterLink` 連到 `{ name: 'home' }`，不寫死路徑（GitHub Pages 有 base）。按鈕用 amber 主色，與占卜頁主要按鈕一致。
  - 左欄只顯示一行「還沒有紀錄」，隱藏關鍵字與篩選（沒東西可篩）。
  - 手機上不顯示「開啟紀錄清單」按鈕，直接看到引導。
  - 這和「有紀錄但篩選後沒有符合」不同：後者右欄照常顯示目前選中的那筆，左欄提示「清除條件」。
- **網址同步**：選中的紀錄寫進 `?id=`（用 `router.replace`，不堆疊瀏覽紀錄）。重新整理或分享給自己時
  可以回到同一筆；id 不存在（被刪或別人的）時，右欄顯示「找不到這筆紀錄」。
- **刪除後**：自動選相鄰的下一筆（沒有就選上一筆）；全部刪完顯示「立即占卜」引導。
- **AI 解讀**：切換到另一筆、或離開頁面時，停止生成中的解讀（避免繼續計費），沿用現有作法。
  補做解讀完成後，更新那一筆摘要的 `hasNarration`，讓「有 AI 解讀」篩選即時反映。
- 各種狀態：左欄載入中（骨架）、載入失敗（顯示原因＋重試）、沒有紀錄（一行文字）；
  右欄載入中、載入失敗、沒有紀錄（「立即占卜」引導）。
  載入中或載入失敗時不能顯示引導，免得已有紀錄的人因為網路慢而看到「還沒占卜過」。

### 需要留意

- `StepResult` 在 `xl` 會排成兩欄牌卡。右欄扣掉 20rem 後大約剩 900px，要實際看過是否擁擠；
  擁擠的話優先在右欄改用 container 寬度判斷，不新增套件。
- 請求一律保留 request id，只認最後一次的回應（快速切換標籤時，先回來的舊詳情不能蓋掉新的）。

## 四、決議紀錄

- **2026-10-27　只改前端，後端沿用 v13**：列表、詳情、刪除三支 API 已經夠用，不為了版面改後端。
- **2026-10-27　左欄一次載入全部摘要，不分頁**：每人最多 100 筆、摘要不含分析與 AI 文字，
  一次載完只要兩次請求。前端篩選因此能涵蓋全部紀錄，不會出現「只篩到這一頁」的誤導。
  如果之後放寬 100 筆的上限，要改成伺服器端搜尋。
- **2026-10-27　檢索只用使用者自己的資料**：比對問題與牌名快照，不在前端判斷牌義或組合，
  符合「解讀文字由後端產生」的規則。
- **2026-10-27　選取寫進網址**：重新整理不會遺失目前看的那一筆；用 `replace` 避免上一頁要按很多次。
- **2026-10-27　收合狀態存 localStorage**：屬於個人閱讀偏好，不值得存到後端；讀不到也不影響功能。
- **2026-10-27　手機清單改為滿版**：原本規劃清單疊在內容上方，改為點開時滿版、選了一筆就收合。
  手機寬度放不下兩欄，清單和內容一次只看一個，比上下疊放更不容易迷路。
- **2026-10-27　標籤只放日期與問題**：原本還有牌陣、張數與 AI 標記，精簡成兩項，
  讓使用者用「什麼時候、問了什麼」找紀錄；其餘資訊在右欄。「有 AI 解讀」篩選保留。
- **2026-10-27　沒有紀錄時右欄放「立即占卜」**：空的頁面直接給下一步，把沒占卜過的會員帶回占卜頁。
  只在確定載入成功且筆數為 0 時顯示，載入中與失敗都不算「沒有紀錄」。
