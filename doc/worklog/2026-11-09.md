### 修正：股市總覽記憶體爆掉（自選清單最慢、甚至不顯示）
- 現象：Cloud Run 記錄 1 小時內 5 次「Memory limit of 512 MiB exceeded」，主機被砍、同時在跑的自選清單與大盤概況回 503，重開後快取全空又更慢（Render 免費方案也是 512MB，推測之前也是同一個原因）
- 原因 1：`dateIn()` 每呼叫一次就 new 一個 `Intl.DateTimeFormat`（約 27KB 原生記憶體、等 GC 才釋放），K 線每根都呼叫；實測 5000 次 +133MB。新增 `src/lib/intlFormat.js` 的 `dateTimeFormat()` 重用格式器，後端 6 處全部改用
- 原因 2：`twseData.js` 的 `cached()` 要等下載完才寫快取，自選清單 N 檔同時查籌碼，同一天的全市場三大法人下載 N 次（8 檔 × 7 天 = 56 次）→ 合併下載中的請求
- 本機實測：三個區塊同時載入的記憶體高峰 490MB → 154MB；8 檔自選的外部請求 72 → 22
- 測試：新增 `memorySafety.test.js`（籌碼只下載一次、失敗後會重下載、格式器重用；確認修正前第一項會失敗），`npm test` 共 345 項通過
- 規則：CLAUDE.md 編輯規則補「記憶體」一條
- market-cron 的 `BACKEND_URL` 已切到 Cloud Run，手動執行成功（Cloud Run 記錄 200、3.7 秒）
- CPU 免費額度估算：每月約 7～9 小時（排程 2～3、瀏覽 1～1.5、AI 約 4），額度 50 小時

### 搬到 us-west1、傳出流量優化
- Cloud Run 從 asia-east1 搬到 us-west1：北美區域才有每月 1 GB 免費傳出流量。整條部署流程（GitHub 連線 `Orange-us`、觸發條件 `tarot-backend-us-west1`、映像倉庫）都在 us-west1，不跨區；台灣的觸發條件、倉庫、連線、原始碼 bucket 已刪，台灣的服務先留著當退路（沒流量不計費）
- 代價：台灣實測純網路來回約 36 → 200 ms、查一次資料庫的 `/api/health` 約 65 → 350 ms（MongoDB Atlas 在亞洲）
- 第一次在 us-west1 部署出現「Container import failed」，重建倉庫後用觸發條件部署就正常，判斷是剛建立倉庫時的暫時性問題
- JSON 回應 gzip：`src/lib/jsonCompression.js`（Node 內建 zlib，不加套件），只包 `res.json`，≥ 1KB 才壓；AI 串流（NDJSON）與圖片不經過。Cloud Run 原本完全不壓縮（實測 `/api/cards` 有沒有帶 gzip 都是 14,972 bytes）
- 牌卡圖片改瀏覽器快取 7 天（原本 `max-age=0`，每次都要跨海問 304）
- 映像倉庫清理規則改成保留 3 版（每版約 170 MB）
- 更正：11/8 那筆約 USD 0.0145 不是主要來自傳出流量（監控顯示台灣那段只傳出約 12 MB），要在帳單報表依 SKU 分組才看得出
- CLAUDE.md 補「傳出流量」規則；部署手冊補第十節（為什麼是 us-west1）與踩過的坑 6、7
- 驗證：`npm test` 349 個全過（新增 `test/jsonCompression.test.js` 4 個）；沒有新增套件
