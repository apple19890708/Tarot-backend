# v15　手動抽牌動畫重寫（GSAP）

建立日期：2026-10-27
狀態：階段 1～6 已實作（2026-10-27），待實際操作確認手感

手動抽牌（步驟 2 的「手動抽牌」）目前是 `FanDeck.vue`：78 張牌背攤在 116° 的扇形裡，
每張牌各自偵測 hover、抬起放大。這一版只改前端的動畫與互動，後端不動。

## 一、目標

現在的問題：

- 相鄰兩張牌只差約 1.5°，每張牌都是自己的 hover 目標，滑鼠稍微移動就在兩張之間來回切換，
  抬起動畫一直被打斷，看起來像疊在一起。
- 78 張一次攤開，每張只露出一條邊，很難看清楚指到哪一張。
- 選到的牌只是在位置格裡淡入，看不出牌是從哪裡來的。
- 洗牌只有「疊起來再展開」，沒有洗牌的感覺。

要做到：

- 指到哪張牌穩定、平順，不再抖動；指到的那張與左右幾張依距離讓開
- 選牌時，牌從扇形飛到對應的位置格，途中翻面露出牌面
- 洗牌有明確的動作（交錯插入），結束後發牌展開成扇形
- 洗完牌先切成三落，使用者選一落再攤開，攤開的張數變少、間隔變寬
- 手機上點第一下抬起預覽，第二下才確定選取
- 有開「減少動態效果」的使用者跳過動畫，功能照常

**不做的事**（這一版不碰）：

- 3D 牌桌、canvas／WebGL 繪製（TresJS、PixiJS）
- 音效、震動回饋
- 拖曳選牌
- 「自動抽牌」與「輸入已抽到的」兩種模式的動畫
- 正逆位與洗牌順序的決定方式（仍由 `HomeView.vue` 的 `shuffleDeck` 決定，動畫只負責呈現）
- 後端修改

## 二、規格

### 套件

- 新增 `gsap`（3.15.0，2026-10-27 經使用者同意）。只用核心、`Flip` 外掛與 `matchMedia`，都在同一個套件裡，免費可商用。
- 每個元件的動畫都包在 `gsap.context()` 裡，元件卸載時 `revert()`，避免換頁後動畫還在跑。
- 「減少動態效果」由 `src/lib/motion.ts` 判斷：開啟時動畫秒數一律為 0（直接跳到結束狀態），飛牌直接略過。

### 指到哪張牌：改用游標角度

- 扇形上蓋一層透明的命中層，用 `pointermove` 從游標位置算出相對扇形圓心的角度，換算成第幾張牌。
  牌本身不再各自偵測 hover。
- 指到的那張抬最高；左右各 2～3 張依距離遞減抬起、往兩旁讓開（放大鏡效果）。
  位移用 `gsap.quickTo` 持續追蹤，不會因為換牌而重新開始動畫。
- 鍵盤操作保留：左右鍵換牌、Enter 選取。

### 洗牌與切牌

1. 進入手動抽牌，或按「重新洗牌」時，播放洗牌時間軸（約 1.2 秒）：
   只用 8～10 張代表牌分成兩疊，交錯插入後收攏。不讓 78 張一起動，畫面乾淨、手機跑得動。
2. 收攏後分成三落，提示「選一落牌」。
3. 選了一落後，其他兩落淡出，選中的那一落（約 26 張）依序發牌展開成扇形。
4. 三落的內容依洗好的牌堆順序切分，資料仍是 `HomeView` 給的 `deck`，動畫不改變牌的順序或正逆位。
   張數最多的牌陣是 10 張，26 張足夠選。

### 選牌：飛入並翻面

- 點選後，用 `Flip` 記下那張牌在扇形裡的位置，在畫面最上層產生一張替身，飛到 `StepDraw.vue` 裡對應的位置格。
- 飛行途中做 3D 翻面（`rotateY`），露出牌面；逆位的牌最後再轉 180°。
- 替身抵達後移除，換成位置格裡的牌圖；扇形裡原本那張變淡（沿用現在的已選樣式）。
- 「收回最後一張」時反向播放：牌從位置格飛回扇形。

### 手機

- 沒有 hover，改成點第一下抬起預覽（顯示同樣的放大鏡效果），再點同一張才確定；點別張就改成預覽那張。
- 扇形半徑沿用現在的斷點設定（`--fan-r`）。

### 元件分工

- `FanDeck.vue`：扇形、命中判斷、洗牌與切牌時間軸。對外仍只發出 `pick`（index），以及新增的「切牌完成」狀態。
- `StepDraw.vue`：提供位置格的 DOM 給飛入動畫當目標。
- `HomeView.vue`：資料與洗牌邏輯不變；「重新洗牌」觸發洗牌時間軸。

## 四、決議紀錄

- **2026-10-27　使用 GSAP**：比較過 Motion for Vue、anime.js、原生 Web Animations API。
  飛入位置格需要 FLIP、洗牌需要多步驟時間軸，GSAP 的 `Flip` 與 timeline 都現成；
  被 Webflow 收購後外掛免費可商用。原生 API 也做得到，但程式碼約多一倍。
- **2026-10-27　命中改用游標角度**：動畫疊加的根本原因是每張牌各自 hover，
  與動畫套件無關。先做這一步就能解決最明顯的抖動。
- **2026-10-27　洗牌只動代表牌**：78 張同時做時間軸容易卡頓，也看不出動作；
  用 8～10 張代表牌示意，結束後再展開真正的牌堆。
- **2026-10-27　加入切牌**：一次攤開的張數從 78 降到約 26，間隔變寬，也符合實際占卜的流程。
  動畫只決定顯示哪一落，不改變牌的順序與正逆位。
- **2026-10-27　先做階段 1～3，看過手感再做 4～6**：命中判斷與飛牌是最直接的改善；
  洗牌、切牌、手機點兩下會改變操作流程，等使用者確認目前的手感後再做。
- **2026-10-27　飛牌替身掛到 body**：步驟卡片有 `backdrop-blur`，會讓 `fixed` 定位相對於卡片而不是畫面，
  替身用 `Teleport` 掛到 `body`（`FlyingCard.vue`）。資料照常立刻更新，飛行期間只藏起終點那張。
- **2026-10-27　修正：命中範圍以「露出的那一條」為準**：原本以牌的中心換算，最左邊那張只露出左緣，
  指在邊緣時算不到。改成每張牌的範圍是自己左緣到下一張左緣，最上面那張到右緣為止。
- **2026-10-27　修正：被指到的牌層級改為總張數＋1**：舊版寫死 60，右側 index 超過 60 的牌會蓋住它。
- **2026-10-27　已選過牌時不再切牌**：切到別的抽牌模式再回來，扇形會重新掛載；
  此時若已有選過的牌，直接攤開那張牌所在的那一落，避免選過的牌不在攤開的範圍內。
- **2026-10-27　洗牌改為循環到使用者按「切牌」**：使用者要求進入手動抽牌就持續洗牌，
  由使用者決定何時停；按下後先收攏敲齊（洗牌可能停在一半），再切成三落。
  減少動態效果時不循環（時間為 0 的動畫無限重播會卡住），直接擺一落牌等按鈕。
- **2026-10-27　自由牌陣與 5 張以上的牌陣切兩落**：使用者要求。兩落各 39 張，張數多的牌陣攤開時可選的牌比較多；
  其餘牌陣維持三落各 26 張。落數由 `StepDraw.vue` 依牌陣決定後傳給 `FanDeck`。
