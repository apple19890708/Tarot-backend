# 正逆位不等於好壞：第九版計畫書

- 建立日期：2026-10-14
- 適用專案：Tarot-backend、Tarot-frontend
- 前置：規則 1～11、牌對辭典（120120 筆）、v8 一致性
- 狀態：草案，待確認
- 來源：v8 第八節原第 6 條，經確認後獨立成版

## 命題

> 逆位不是負分，正位不是加分。逆位是能量的**表達方式**不同，不是分數高低。

這句話沒有爭議，問題是系統有多少地方違反它。本版先把範圍盤清楚，再決定要改到哪一層。

**這版會動到辭典的 120120 筆與整個量化模型，是目前為止影響面最大的一版。** 不建議和 v8 並行。

---

## 一、現況盤點：哪些地方預設了「正＝好、逆＝壞」

盤查了五層，結論是**三層已經做對、兩層全錯**。

### 1.1 量化模型（規則 11）—— 已經做對

`ruleConfig.js:163`：

```js
const QUANT = {
  // 逆位：衰減外顯強度，不翻轉正負（規則 6）
  reversedAttenuation: 0.45,
```

`quantRules.js:70`：`v = polarity × relevance × orientation × intensity`，其中 `orientation` 是 1 或 0.45。

**逆位只是把力道打到 0.45 倍，不會把正值翻成負值。** 牌本身的好壞由 `polarity` 決定，而 `polarity` 是逐張標注的（`cardDimensions.js`：寶劍三 −0.9、聖杯十 +0.9、權杖七 0）。

這層的設計是對的，v4 當初就想清楚了。

### 1.2 單張牌的極性表 —— 已經做對

`cardDimensions.js` 有 45 張覆寫，例如：

| 牌 | polarity | 註解 |
|---|---|---|
| 寶劍三 | −0.9 | 心碎，比數字 3 推導的 +0.5 嚴重得多 |
| 錢幣五 | −0.7 | 匱乏、被排除 |
| 權杖七 | 0 | 防守、堅持立場，中性 |
| 聖杯九 | +0.7 | 願望成真、滿足 |

**正位的牌一樣可以是負分**，這正是 v7 修「正位卻說拖」時依賴的機制。

### 1.3 跨花色辭典短語 —— 已經做對

v8 之前補的 `_phrases/*.js` 用 `uBad` / `rGood` 兩個旗標逐張標記，連接詞看語意正負而非正逆位。例如聖杯五：

```js
聖杯五: { u: '還在為失去的那塊難受', r: '注意力慢慢轉回剩下的',
          uBad: true, rGood: true }
```

### 1.4 動能與阻力（規則 10／11）—— **錯**

`quantRules.js:91`：

```js
const momentum = rows.reduce((sum, row) =>
  sum + (row.orientation === 1 ? row.weight * row.relevance : 0), 0) / totalWeight
```

`weightRules.js:42`：

```js
const reversedWeight = items.filter((item) => item.orientation === 'reversed')...
const reversedWeightRatio = reversedWeight / total
let resistance = reversedWeightRatio >= 0.5 ? 'high' : ...
```

**`momentum` 只累計正位、`resistance` 直接等於逆位權重比。** 和牌本身是好是壞完全無關 —— 一副全是正位的寶劍三、寶劍九、寶劍十，會算出 momentum 高、resistance 0，講成「使得上力、大致順利」。

這是 v7「全正位但走向不順」那個矛盾的真正根因。當時我只改了措辭，沒動算法。

### 1.5 位置規則與配對線索 —— **錯**

`positionRules.js:12`：

```js
} else if (present.orientation === 'reversed' && future.orientation === 'upright') {
  // →「由逆轉正，有解套的走勢」
} else if (present.orientation === 'upright' && future.orientation === 'reversed') {
  // →「由正轉逆，受阻」
```

`analysisFormatter.js` 的 `NEUTRAL_CLUES`：

```js
['blocked',   '由正位轉為逆位，前一張的狀態到這裡受阻'],
['unblocked', '由逆位轉為正位，有解套的跡象'],
```

兩處都把方向當成好壞。寶劍九逆位→寶劍十正位會被說成「由逆轉正，有解套的走勢」，實際上是從焦慮走到結束，完全不是解套。

### 1.6 同花色與大牌辭典 —— **大致錯，但要個別確認**

v5 階段寫的 `pairs/<domain>/{major,swords,cups,wands,pentacles}.js` 共 3654 組／領域，四段文字的排列是：

```
[0] 正正   [1] 正逆   [2] 逆正   [3] 逆逆
```

當時的寫法多半預設 `[0]` 最好、`[3]` 最差。抽查可以看出問題：

| 牌對 | [0] 正正 | [3] 逆逆 |
|---|---|---|
| 錢幣王牌→錢幣二（人際） | 認識了實在的人，也還應付得過來。 | 既沒新朋友也應付不來，很吃力。 |
| 節制→月亮（財務） | 就算控制好比例，標的本身不透明仍是風險。 | 分寸與判斷都不到位，暫停。 |

第一組確實是「正好逆壞」的直覺寫法；第二組的 `[0]` 其實是警告，寫得是對的。**所以不是全錯，要逐組看。**

## 二、問題的真正形狀

盤完之後，原本模糊的「正逆位預設」收斂成三個具體缺陷：

| # | 缺陷 | 位置 | 嚴重度 |
|---|---|---|---|
| P1 | `momentum` 與 `resistance` 只看正逆位，不看牌本身好壞 | `quantRules.js`、`weightRules.js` | **高**。直接造成 v7 那類矛盾 |
| P2 | 位置規則與配對線索把「轉正／轉逆」當成「變好／變壞」 | `positionRules.js`、`NEUTRAL_CLUES` | 中 |
| P3 | 同花色／大牌辭典部分條目預設正好逆壞 | `pairs/<domain>/*.js`，3654 組 × 5 領域 | **高**，但只有一部分需要改 |

## 三、改法

### 3.1 P1：動能與阻力改看極性，不只看正逆位

概念上要區分兩件事：

| 概念 | 現在 | 應該是 |
|---|---|---|
| 能不能使上力（momentum） | 正位的權重比 | **正向極性**的加權佔比（`polarity > 0`，逆位打 0.45 折） |
| 卡不卡（resistance） | 逆位的權重比 | **負向極性**的加權佔比 ＋ 逆位帶來的額外折損 |

```js
// 動能：牌本身是正向的，而且力道出得來
const momentum = Σ(weight × max(0, polarity) × orientation) / totalWeight

// 阻力：負向的牌造成的拖累，加上逆位讓力道出不來的部分
const resistance =
  Σ(weight × max(0, -polarity)) / totalWeight          // 牌義本身的拖累
  + Σ(weight × max(0, polarity) × (1 - orientation)) / totalWeight  // 逆位損失的推力
```

全正位的寶劍三／九／十：momentum ≈ 0、resistance 高 —— 符合直覺。
全逆位的聖杯十／九：momentum 不為 0（只是打折）、resistance 中等 —— 也符合。

**相容性**：`weights.reversedWeightRatio` 這個欄位要保留（前端可能在用），但文字不再拿它當阻力。

### 3.2 P2：方向性措辭改成「表達方式改變」

| 現行 | 改為 |
|---|---|
| 由逆轉正，有解套的走勢 | 從內收轉為外顯，這股能量開始往外走 |
| 由正轉逆，受阻 | 從外顯轉為內收，力道轉向內部 |
| 由正位轉為逆位，前一張的狀態到這裡受阻 | 由正位轉為逆位，同一股力量換成往內走 |
| 由逆位轉為正位，有解套的跡象 | 由逆位轉為正位，原本壓著的開始浮上來 |

好壞交給極性去講，方向只講方向。

### 3.3 P3：辭典逐組檢查（規模最大）

3654 組 × 5 領域 = 18270 組要看。**不可能逐組人工重寫**，分兩步：

**第一步：自動篩出可疑條目。** 用 `cardDimensions` 的 polarity 推算每組的「預期好壞」，和實際文字的情緒傾向比對，標出不一致的。情緒傾向可以用關鍵詞表粗篩（「好在」「也」vs「但」「既…也」），這些連接詞在既有條目裡是固定的，可以當訊號。

**第二步：只改篩出來的。** 預估需要改的是兩端極化的牌（寶劍三／九／十、錢幣五、聖杯五、高分正向牌），不是全部。

篩選腳本要先寫、先看數量，再決定要不要全改。**在看到數量之前不承諾範圍。**

### 實作與原計畫的差異

**C 期的第一版篩選是錯的，重寫過。** 原本打算用連接詞與關鍵詞判斷每段文字的語氣，實測後廢棄，原因有兩個：

1. 關鍵詞比對不可靠 ——「這種位子坐不穩」被『穩』判成正面、「這很難得」被『很難』判成負面。
2. 前提本身就錯。第一版假設「正極性的牌逆位仍該讀成好事」，於是把「既沒團隊也沒熱情」標成錯誤。
   但正面牌逆位代表**那份好沒展現出來**，辭典寫得是對的。

改用一條不必判斷語氣、塔羅上也站得住的規則：

> 一張本質負面的牌，逆位是「那股負面能量沒有全力展開」，相對是鬆一口氣。
> 所以兩張牌本質都負面時，四格的嚴重程度應該是 [0] 正正最重、[3] 逆逆最輕。

既有辭典的 [3] 幾乎一律是「既…也…，<最壞的收尾>」，落在這個條件上就是預設錯了。

**篩出 385 筆**（工作 74、財務 80、感情 80、人際 77、學業 74），佔「兩張都負面」的 774 組約一半。

**D 期**用 `scripts/fixPolarityTexts.js` 改寫：為 13 張本質負面的牌各寫 5 個領域的「逆位鬆開」短語（65 句），再組成「A，B，<收尾>。」收尾五句輪替，避免 385 句長得一樣。

```
舊：既沒止損也睡不好，先停手。
新：傷口在癒合，焦慮在退，這時候適合重新整理。
```

改完重跑稽核：**385 → 0**。
