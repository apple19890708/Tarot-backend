# v26　每日一牌與月曆、占卜日記、會員選單、通知中心

建立日期：2026-11-20
狀態：進行中（計畫 1、2、2-2、3、5 完成；推播提醒暫不做（D7）；計畫 4 已刪除）

## 一、目標

功能越來越多，使用者需要「每天回來」的理由、「事後回頭看」的地方，以及一個收通知的地方。這一版分成以下計畫（計畫 4 分享卡片已在 2026-11-20 刪除，編號保留不重排）：

1. **每日一牌＋月曆**：每天抽一張牌。做一個好看的月曆，每一天顯示當天的每日一牌，以及當天問過的占卜紀錄。
2. **占卜日記**：在「我的紀錄」的每一筆占卜（以及每日一牌）多一個日記頁，讓使用者寫這件事後來的發展。編輯器參考 Notion 的手感。
   - **股票日記**（2026-11-20 追加）：股票分析的日記改成「一檔股票一本」，不是每次分析各一本。
3. **會員選單**：桌面版頂欄的功能連結收進「會員頭像／名字」的下拉選單，點頭像才展開。
4. ~~分享卡片~~：2026-11-20 使用者刪除，不做。
5. **通知中心**：頂欄右上角一個鈴鐺，收齊價位提醒、除息提醒等通知，看過、刪除都在這裡管理。

### 不做的事

- 每日一牌不呼叫 AI（只用牌義與規則的一句提醒），不增加 AI 費用。要加 AI 短解讀之後另外評估。
- 日記內容**不送給 AI**、不出現在任何公開頁面（隱私）。
- 日記先不支援上傳圖片、表格、多人共編、版本紀錄。
- 不做分享卡片（計畫 4 已刪除）。
- 通知中心不做即時連線（WebSocket），用定時查詢；不寄 email。
- 不做社群功能（留言、按讚、追蹤別人）。
- 會員頭像先不支援上傳照片。

## 二、規格

### 計畫 1：每日一牌＋月曆

**每日一牌**

- 每位會員每天（台北時間的一天）一張，牌與正逆位隨機。抽出後當天固定，不能重抽（見決定事項 D1）。
- 未登入也能抽，但不存、不進月曆，畫面提示「登入後可以存進月曆」。
- 內容：牌面圖（逆位倒過來）、牌名與正逆位、牌義重點（現有牌義的「核心訊息」）、一句今日提醒（由後端規則產生，文字由後端給，前端不組句子）。
- 連續天數：月曆與每日一牌畫面顯示「已經連續 N 天」。
- 推播提醒（可選）：使用者在帳號設定或月曆開啟「每天幾點提醒我抽牌」。沿用現有的瀏覽器推播（`webPush`、`PushSubscription`）。

**月曆**

- 新頁面 `/calendar`（要登入），從會員選單進入（計畫 3）。
- 月檢視：每一格顯示當天的每日一牌縮圖、當天的占卜紀錄數（小圓點或數字）、有日記時的記號。今天加框，未來的日子淡化。
- 點某一天：打開當天的面板（桌機在右側、手機是底部彈窗）。內容有當天的每日一牌、當天的占卜紀錄清單（問題、牌陣、點了進紀錄）、當天寫的日記（計畫 2）。
- 「今天問過的相關紀錄」先只算**塔羅占卜紀錄**；個股分析、財經新聞分析要不要也放進月曆，見決定事項 D2。
- 換月：上一月／下一月／回到今天。資料一次抓一個月。
- 樣式沿用專案的像素與玻璃風格、日夜模式語意色；載入中用 `SkeletonBlock` 畫出同形狀的月曆骨架；彈窗用 `useScrollLock`。

**月曆套件**（使用者要求找套件；第一次加入前要使用者同意）

| 選項 | 授權 | 最新版 | 優點 | 缺點 |
|---|---|---|---|---|
| **FullCalendar**（`@fullcalendar/vue3`＋`daygrid`） | MIT（月檢視免費） | 7.1.x | 最成熟、月檢視完整、格子內容可以用 slot 自訂（放牌卡縮圖）、手機也能用 | 套件較大（約 100KB 以上）、預設樣式要大量覆蓋才會是像素風 |
| vue-cal | MIT | 4.10.x（Vue 3） | 輕、格子可自訂 | 月檢視比較陽春，文件較少 |
| 自己做 | — | — | 最輕、樣式完全照專案（現有股利頁的月份小卡就是自己做的） | 換月、週起始、跨月格子要自己處理 |

建議：**FullCalendar**。理由是使用者要「好看、可客製」，它的格子 slot 可以完整放牌卡圖，換月與鍵盤操作都做好了；頁面用動態載入，不影響其他頁的大小。安裝時選至少兩週前發布的版本（目前 7.1.5 是 11/12 發布，裝的時候再確認）。

**資料與 API**

- 新 model `DailyCard`：`user`、`date`（台北日 `YYYY-MM-DD`）、`cardId`、`orientation`、`createdAt`；`user + date` 唯一。
- `GET /api/daily-card/today`：今天抽過就回那張，沒抽過回 `null`。
- `POST /api/daily-card/draw`：今天沒抽過才抽；同時送兩次也只會有一張（唯一索引擋住）。
- `GET /api/calendar?month=2026-11`：回這個月每一天的每日一牌、占卜紀錄摘要（id、問題、牌陣、時間）、日記數。只查自己的資料。
- 推播排程：新增 GitHub Actions `daily-card-cron`（每小時整點），呼叫後端端點，寄給「提醒時間是這一小時、今天還沒抽」的人（做法同 `market-cron`，用同一個排程密鑰）。

### 計畫 2：占卜日記

- 每一筆**塔羅紀錄**與**每日一牌**都可以寫多篇日記（後續追蹤），依時間排成一條時間軸。
- 每篇日記有：內容、日期、**結果標記**（還不知道／應驗了／部分應驗／沒有應驗，可不選）。結果標記之後可以拿來統計「準不準」（是非題、時間題的命中率），補上 v25 的回饋只問「有沒有幫助」的缺口。
- 進入點：
  - 我的紀錄的每筆塔羅紀錄多一個「日記」分頁或區塊。
  - 月曆當天的面板。
  - 每日一牌畫面的「寫點什麼」。
- 可選提醒：寫占卜時可以勾「兩週後提醒我回來看看」（推播），預設不勾。

**編輯器：Notion 的手感**

- 套件：**Tiptap 3**（`@tiptap/vue-3`、`@tiptap/starter-kit`、`@tiptap/extension-placeholder`、`@tiptap/suggestion`、`@tiptap/extension-drag-handle-vue-3`，都是 MIT，官方支援 Vue 3）。第一次加入前要使用者同意。
- 要有的 Notion 手感：
  - 空白時顯示「輸入 / 叫出選單」。
  - 打 `/` 跳出區塊選單：標題、清單、編號清單、待辦清單、引用、分隔線、重點標示。
  - 區塊左側拖曳把手，可以上下拖。
  - Markdown 快捷鍵：`# `、`- `、`[] `、`> `。
  - 選取文字時出現小工具列：粗體、斜體、刪除線、標示。
- 比較過的其他選項：
  - Milkdown：以 Markdown 為主，Notion 式區塊操作要自己補。
  - Editor.js：區塊式很像 Notion，但 Vue 整合是社群套件，型別與維護較弱。
  - BlockNote：最像 Notion，但只支援 React。
- 儲存：存 Tiptap 的 JSON（不是 HTML），另存一份純文字摘要給清單與月曆顯示。
  - 後端驗證節點類型白名單與大小（例如每篇 50KB 以內）。
  - 顯示時用唯讀的編輯器渲染，不用 `v-html`，避免 XSS。
- 草稿：編輯中自動存到 localStorage（包 try/catch），網頁關掉再開不會不見；按「儲存」才送後端。
- 刪除日記用 `confirmDialog`。

**資料與 API**

- 新 model `JournalEntry`：`user`、`target`（`{ kind: 'reading' | 'daily', id }`）、`content`（JSON）、`text`（摘要）、`outcome`（`null | 'hit' | 'partial' | 'miss'`）、`entryDate`、`createdAt`、`updatedAt`。獨立一個 collection，不塞進 Reading（避免紀錄文件越長越大）。
- `GET /api/journal?target=reading:<id>`、`POST /api/journal`、`PUT /api/journal/:id`、`DELETE /api/journal/:id`。全部只能動自己的（權限判斷照現有 readings 路由的寫法，路由改完照規範請 api-reviewer 審查）。
- 刪除一筆塔羅紀錄時，它的日記一起刪。

### 計畫 2-2：股票日記（一檔股票一本）

2026-11-20 使用者要求：股票分析的日記不要像塔羅一樣「每次分析是一件事」，而是**針對這支股票的總集**。例如 0050 做了 3 次分析，寫日記時進到「0050 的日記頁」，左邊看得到這檔所有的分析紀錄，右邊是日記，而且要有一些「記錄股票」的功能。

**頁面**

- 網址 `/journal/stock/<市場>/<代號>`（例如 `/journal/stock/tw/0050`、`/journal/stock/us/NVDA`）。
- 左欄：這檔股票**所有的 AI 分析紀錄**，新的在上。每筆一張卡（日期、分析時股價、漲跌），點開看全文（沿用 `StockAnalysisDetail`）。最上面一塊「這檔的摘要」：分析過幾次、第一次與最近一次的日期與股價、日記幾篇。
- 右欄：日記（沿用現在的編輯器、標題、列表與滿版編輯），加上下面的股票欄位。
- 入口：我的紀錄的股票分析「日記」→ 那檔的日記頁；股市追蹤的個股分析彈窗加「日記」；月曆當天的日記清單點進去也到那檔。

**記錄股票的功能（每篇日記可選填）**

- **動作**：觀察／買進／加碼／減碼／賣出／停損（單選，可不選）。
- **價格**與**數量**（台股可填張或股，沿用 `quantityUnit` 的換算）。
- **寫的時候的股價**：開日記時自動帶入最新收盤價（免費報價來源，不呼叫 AI），存進這篇，之後看得到「寫的時候是多少、現在是多少」。
- **目標價、停損價**：這篇設定的，列表上顯示；之後可以接價位提醒（一鍵建立提醒，用現有的 `MarketAlert`）。
- **結果標記**沿用：判斷後來對了／部分／錯了／還不知道。
- 列表卡片多顯示：動作標籤、價格、寫的時候的股價與到現在的漲跌。
- 這些欄位**只是紀錄**，不會自動改「股市追蹤」的持股（持股仍在追蹤清單裡記，避免兩邊對不起來）。

**資料與 API**

- `JournalEntry.targetKind = 'stock'` 的 `targetId` 改成 `<市場>:<代號>`（例如 `tw:0050`），不再是分析紀錄的 id。
- 新欄位（只有股票日記用）：`stock: { action, price, quantity, unit, quoteAtWrite, targetPrice, stopPrice }`，後端驗證數值範圍。
- 新增時確認這檔是使用者分析過或追蹤中的股票（不能寫任意代號，避免灌資料）。
- 刪除某一筆分析**不再**連帶刪日記（日記屬於這檔股票，不屬於某一次分析）；刪帳號照樣全刪。
- 既有資料：2026-11-20 已經寫在單一分析底下的日記（`stock:<分析 id>`），用一次性轉換改成那筆分析的股票（見 D9）。
- `GET /api/market/analyses?symbol=` 讓左欄只抓這檔的分析。

### 計畫 3：會員選單

- **桌面版頂欄**：只留品牌（Tarot Bar）、主要動作「占卜」、會員頭像＋名字。其他功能收進頭像的下拉選單。
- **下拉選單內容**（依登入狀態與權限顯示）：
  - 我的紀錄、月曆、占卜日記（計畫 1、2）。
  - 股市追蹤（有金融股市權限才顯示）。
  - 帳號設定。
  - 管理者才有：會員、路由管理。
  - 登出。
- **頭像**：目前會員沒有頭像欄位，先用名字的第一個字做成圓形頭像（像素風邊框、accent 色）。之後要上傳照片再另外做。
- **互動規範**（照 ui-check 的彈出層規則）：
  - 點外面、按 Esc、選了項目都會關閉。
  - 鍵盤可以上下選。
  - 目前所在的頁面要高亮。
  - 管理者顯示 admin 標籤。
- **手機版**：拿掉漢堡，點頭像開同一份選單（D5）。實作時改成從頂欄下方整排往下展開，不用底部彈窗：使用者先前把月曆的底部抽屜改成「從上而下」，選單照同一個方向。
- **未登入**：頂欄維持「登入」「註冊」按鈕。

### 計畫 5：通知中心

**目標**：推播與網頁上跳出的提示送出去就沒了，錯過就找不回來。頂欄右上角放一個鈴鐺，收齊所有通知，可以回頭看、標成已讀、刪除。

**畫面**

- 位置：頂欄右上角，會員頭像（計畫 3）的左邊。鈴鐺上顯示未讀數（超過 99 顯示 99+）。
- 點鈴鐺打開通知面板（桌機是下拉，手機是底部彈窗，照 ui-check 彈出層規則：點外面、Esc 關、背景不捲）。
- 面板內容：
  - 上方：「全部標成已讀」「清除已讀」。
  - 列表：依日期分組（今天、昨天、更早），每則有種類圖示、標題、一句內容、時間；未讀的有小點。
  - 點一則：標成已讀並前往相關頁面（例如價位提醒 → 股市追蹤那一檔）。
  - 每則可以單獨刪除；清除前用 `confirmDialog`。
  - 沒有通知時顯示空白提示；載入中用骨架。
- 網頁上現在右下角跳的價位提醒提示照樣跳，同時也進通知中心。

**通知來源（第一版）**

- 價位提醒觸發（`notifier.notifyAlerts`）。
- 除息前一個交易日提醒（`exDividendReminder` → `notifier.notifyUser`）。
- 測試推播（帳號設定的「送測試通知」）。
- 之後的來源（不在第一版）：每日抽牌提醒、日記回顧提醒（D7 推播做的時候一起接）。

**資料與 API**

- 新 model `Notification`：`user`、`kind`（`price-alert`／`ex-dividend`／`test`／`system`）、`title`、`body`、`url`（站內路徑）、`readAt`、`createdAt`。
- 寫入時機：在 `notifier` 送推播的同一個地方先存一筆，**推播失敗或使用者沒開推播也照樣存**（通知中心就是補這個缺口）。
- 保留：每人最多 200 則，超過刪最舊；超過 90 天自動刪（TTL 索引）。見 D11。
- `GET /api/notifications`（分頁）、`GET /api/notifications/unread-count`、`PUT /api/notifications/read`（全部或指定 id）、`DELETE /api/notifications/:id`、`DELETE /api/notifications?read=true`（清除已讀）。都只動自己的。
- 刪除帳號時一起刪（`USER_DATA_MODELS`）。

**更新方式**

- 不做 WebSocket。未讀數在換頁時、分頁回到前景時、以及每 60 秒（分頁在前景才查）查一次。
- 收到推播時（Service Worker 的 `push` 事件）通知前景分頁重新查未讀數。

**不做**

- email 通知、通知種類的開關設定（之後再說）、即時連線。
