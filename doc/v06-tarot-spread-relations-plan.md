# 牌陣關係對：第六版計畫書

- 建立日期：2026-10-13
- 適用專案：Tarot-backend、Tarot-frontend
- 前置：規則 1～11、牌對辭典（v5）
- 狀態：草案，待確認

## 目標

把「**相鄰兩張配對**」一般化為「**牌陣自己定義的關係對**」，並新增塞爾特十字作為第一個需要非相鄰關係的牌陣。

---

## 一、為什麼不往 3 張以上的組合辭典走

先把路堵死，避免之後又繞回來。

| 張數 | 有序組合 | × 正逆位 | 總筆數 | 單一領域生成成本 |
|---|---|---|---|---|
| 2 | 6,006 | × 4 | 24,024 | 約 US$70 |
| 3 | 456,456 | × 8 | 3,651,648 | 約 US$20,000 |
| 4 | 34,234,200 | × 16 | 5.5 億 | 約 US$300 萬 |

3 張牌的辭典光儲存就要約 730 MB，超過 Atlas 免費方案；成本也高到不切實際。**查表法到 2 張就是上限，這是數學問題，不是工程問題。**

3 張以上的「整體」本來就該由另外三種機制處理，而且**都已經在跑**：

| 機制 | 由誰負責 | 能處理任意張數嗎 |
|---|---|---|
| 整體統計特徵（花色主導、數字階段、權重、指向） | 規則 2／3／9／10／11 | 可以，它看的是分布不是組合 |
| 型態判定（連續同花色、三張大牌…） | 規則 2／9（可再擴充） | 可以 |
| 整體統整敘述 | AI 解讀（現場生成） | 可以 |

本版要補的是中間那層：**特定位置之間的關係**。

---

## 二、核心轉變

### 現況

所有牌陣一律「相鄰兩張配對」：`1→2`、`2→3`、`3→4`…

對時間之流合理（過去→現在→未來本來就是序列），但對其他牌陣不準確：

- 直指核心的「問題核心」與「障礙」不是先後關係，是**橫跨**
- 塞爾特十字的「根基」與「意識」**不相鄰**，但那組對照才是精髓

### 改為

每個牌陣自己宣告「哪些位置之間有關係、是什麼性質」：

```js
{
  key: 'celtic-cross',
  positions: [ ... ],
  relations: [
    { from: 0, to: 1, kind: 'crossing' },
    { from: 2, to: 4, kind: 'depth' },
    // ...
  ],
}
```

沒有宣告 `relations` 的牌陣，**自動退回相鄰配對**，所以現有牌陣不設定也能照舊運作。

## 三、關係型態（kind）

| kind | 中文 | 語意 | 文字框架 |
|---|---|---|---|
| `sequence` | 順承 | 前者走到後者 | 「A 走到 B：…」 |
| `crossing` | 橫跨 | 後者擋在前者面前 | 「擋在 A 前面的是 B：…」 |
| `contrast` | 對照 | 兩者的落差 | 「A 與 B 的落差：…」 |
| `depth` | 表裡 | 表面與底下 | 「表面是 A，底下是 B：…」 |
| `remedy` | 對策 | 後者用來處理前者 | 「面對 A，B 是可用的方式：…」 |
| `projection` | 投射 | 期待與實際 | 「你期待 A，實際可能是 B：…」 |
| `arc` | 整體弧線 | 起點到終點 | 「從 A 到 B 這條線：…」 |

### 辭典如何重用（重點）

**辭典的 key 不加入 kind**，維持 `(牌A正逆, 牌B正逆, 領域)`。kind 只負責外層的框架句。

這樣 v5 已經生成的內容**原封不動全部可用**，不會因為新增牌陣而讓成本再乘以 7。

**誠實說明限制**：辭典內容是以「前者接到後者」的語氣寫的，套到 `crossing`、`contrast` 這類框架時，偶爾會讀起來略有落差。若實測後覺得 `crossing` 特別不順，再單獨為它生成一批變體即可（只需 6,006 × 4 筆，不是全部 kind 都做）。

## 四、與規則 8 的重疊（必須先解決）

規則 8（各個位置看出什麼）**已經在做位置配對判定**：

| 現有判定 | 實際上就是 |
|---|---|
| `adviceVsChallenge`（障礙×對策） | `remedy` 關係對 |
| `supportVsNegative`（負面×正面影響） | `contrast` 關係對 |
| `endpoints`（問題×終局、過去×未來） | `arc` 關係對 |
| `orientationTrend`（過去／現在／未來三張） | 三張，不屬於關係對 |
| `resourceBlocked`、`coreMajor`、`supportBlocked`、`negativeEasing` | 單一位置判定 |

**如果不處理，同一組牌會在「牌跟牌之間的關係」和「各個位置看出什麼」各講一次**，就像先前阻力重複出現的問題。

### 處理方式

把規則 8 拆成兩半：

- **配對型判定** → 移交給關係對系統（`adviceVsChallenge`、`supportVsNegative`、`endpoints`）
- **單一位置判定** → 留在規則 8（`resourceBlocked`、`coreMajor`、`supportBlocked`、`negativeEasing`）
- **三張型判定** → 留在規則 8（`orientationTrend`）

規則 8 的元素關係判斷（例如「對策能克制障礙」）不會消失，而是變成關係對文字的一部分。

## 五、塞爾特十字

### 5.1 位置與權重（總和為 1）

| # | 位置 | 說明 | 權重 |
|---|---|---|---|
| 1 | 現況 | 事情目前的核心狀態 | 0.15 |
| 2 | 阻礙 | 橫跨在現況上的力量 | 0.12 |
| 3 | 根基 | 潛意識、沒說出口的動機 | 0.08 |
| 4 | 過去 | 剛過去、正在淡出的影響 | 0.06 |
| 5 | 意識 | 你認為自己要的、表面目標 | 0.09 |
| 6 | 近未來 | 接下來即將發生的 | 0.10 |
| 7 | 自我 | 你在這件事裡的姿態 | 0.08 |
| 8 | 環境 | 他人與外在條件 | 0.07 |
| 9 | 希望與恐懼 | 最期待也最害怕的 | 0.08 |
| 10 | 結果 | 照目前走向的結局 | 0.17 |

**權重設計理由**：結果（0.17）與現況（0.15）最重；阻礙（0.12）次之，因為它決定事情推不推得動；過去（0.06）最輕，它是正在淡出的影響。

### 5.2 關係對（6 組）

| 位置 | kind | 為什麼是這組 |
|---|---|---|
| 1 現況 × 2 阻礙 | `crossing` | 塞爾特十字的核心，橫跨的那張就是問題所在 |
| 3 根基 × 5 意識 | `depth` | 潛意識與表意識的落差，常是真正的答案 |
| 4 過去 × 6 近未來 | `sequence` | 時間軸上的推進 |
| 7 自我 × 8 環境 | `contrast` | 內在認知與外界現實的對照 |
| 9 希望恐懼 × 10 結果 | `projection` | 期待與實際走向的差距 |
| 1 現況 × 10 結果 | `arc` | 整段的起點到終點 |

**修正（實作時發現）**：原本寫「4 組不相鄰」是錯的，我把「語意上不是順承」和「索引上不相鄰」混為一談。正確的數字是：

- **索引不相鄰 3 組**：根基×意識（2,4）、過去×近未來（3,5）、現況×結果（0,9）
- **語意上不是順承 5 組**：除了過去×近未來之外全部都是（橫跨、表裡、對照、投射、整體）

兩個數字都說明同一件事：**相鄰配對模型只能表達這 6 組裡的 1 組**，其餘 5 組不是位置搆不到，就是關係性質根本不同。

### 5.3 規則 8 要補的單一位置判定

- 根基為大牌：真正的動力來自自己也未必察覺的層面
- 希望恐懼逆位：期待與恐懼糾纏，自己也分不清想要什麼
- 環境逆位：外在支持不足，或他人的態度不明朗

## 十、牌陣排列圖（已確認要做）

**所有牌陣都要畫出實際排列並說明每個位置代表什麼**，不只塞爾特十字。

### 10.1 資料結構

每個位置新增 `layout`，以網格座標表示：

```js
{ key: 'present', label: '現況', prompt: '...', weight: 0.15,
  layout: { col: 2, row: 2 } }
```

- `col` / `row`：從 1 開始的網格座標
- `overlay: true`：疊在同一格的另一張牌上（只有塞爾特十字的「阻礙」用到，傳統上橫跨在「現況」之上）
- 每個牌陣另外宣告 `grid: { cols, rows }`

### 10.2 四個牌陣的排列

**時間之流（3 張，3×1）** — 時間由左到右

```
[1 過去] [2 現在] [3 未來]
```

**直指核心（4 張，3×3）** — 核心居中，障礙與對策左右對峙，資源在下支撐

```
         [1 核心]
[2 障礙]          [3 對策]
         [4 資源]
```

**指引之星（7 張，5×3）** — 時間軸橫貫中央，負面在上、正面在下，問題與終局分列兩端

```
              [3 負面影響]
[1 問題] [2 過去] [4 現在] [6 未來] [7 終局]
              [5 正面影響]
```

**塞爾特十字（10 張，4×4）** — 左側十字、右側權杖，阻礙橫跨在現況之上

```
            [5 意識]              [10 結果]
[4 過去]  [1 現況/2 阻礙]  [6 近未來]  [9 希望恐懼]
            [3 根基]              [8 環境]
                                  [7 自我]
```

### 10.3 顯示位置

同一個元件在兩個地方使用：

| 情境 | 顯示內容 |
|---|---|
| 選牌陣時（抽牌模式） | 空的排列圖，標出位置編號與名稱，滑過顯示該位置的含義 |
| 看結果時 | 同樣排列，但填入實際抽到的牌（縮圖、正逆位） |

這樣使用者在抽牌前就知道這個牌陣在問什麼，看結果時也能對照位置理解。

### 10.4 實作

- 新增 `src/components/SpreadLayout.vue`，以 CSS Grid 繪製，`cards` 為選填
- 手機版縮小卡片尺寸，必要時水平捲動（塞爾特十字 4 欄在窄螢幕會擠）
- 「阻礙」用 `rotate-90` 疊在「現況」上，呈現傳統的橫跨樣式
