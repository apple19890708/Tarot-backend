# 塔羅量化分析：第四版計畫書（指向化與視覺化）

- 建立日期：2026-10-12
- 適用專案：Tarot-backend、Tarot-frontend
- 前置：規則 1～10（見 `v01-tarot-combination-rules-plan.md`、`v02-tarot-combination-rules-plan.md`）
- 狀態：已完成（2026-10-12）

## 目標

把現有的「質化規則判斷」延伸為一組**有界、可比較的數值指標**，用來回答「這組牌對你問的問題，指向哪個方向、力道多強」，並據此做視覺化（雷達圖、傾向條、指向儀表）。

本版**不取代**現有規則引擎，而是在它算好的 `profiles` 與 `analysis` 之上新增一層 **規則 11：量化指標**。既有文字分析與 AI 解讀完全不受影響。

---

## 一、與參考方案的差異（重要）

參考方案（外部 AI 產出的 DI 公式）方向正確，但有四處若照抄會與本專案衝突或在數學上不成立。以下為本計畫採用的修正，**差異處皆以本計畫為準**。

| # | 參考方案 | 問題 | 本計畫作法 |
|---|---|---|---|
| 1 | 逆位乘 `-0.6`（負數） | 乘負數在數學上等於「牌義相反」，直接違反**規則 6 的決議**：逆位是受阻、內化、延遲或過度，不是單純相反 | 逆位**衰減**外顯強度（乘 0.45，正值），另外把逆位計入獨立的「阻力」軸，不翻轉正負號 |
| 2 | `base_weight`（大牌 3）直接乘進分數 | 值域爆開到 ±3 以上，所以才需要 `max/min` 硬夾，且夾擠會讓極端值全部黏在 ±100 失去鑑別度 | 大小牌權重放進**加權平均的分母**（`Σ(w·v)/Σw`），值域自然落在 −1～1，無需夾擠 |
| 3 | `* 33.3` 正規化 | 魔術數字，來源不明，且與上一點的夾擠互相補洞 | 每張牌的投影值由建構上即落在 −1～1，加權平均後 ×100 即為 −100～100，**無魔術常數、無夾擠** |
| 4 | 手寫 78 張 × 4 維度 = 312 個數字 | 內容工作量大；且四維度（行動／物質／情感／理性）**本來就等同四元素**（火／土／水／風），小牌的維度向量幾乎就是花色的 one-hot | 小牌由「花色 + 數字主題 + 宮廷階級」**自動推導**，零標註；僅大牌 22 張需人工標註（88 個數字），且先給元素推導的預設值，可漸進修正 |

此外，參考方案的 `domain_weights` 對 business 給 `emotion: -0.1`（負值），意思是「情感正向的牌會**降低**商業分數」。本計畫改為**非負的關注度權重**（該領域在意什麼），正負向另由獨立的極性維度表達，避免語意混淆。

## 三、資料結構

### 3.1 維度向量（四軸）

四個維度與四元素一一對應，這不是巧合，而是塔羅花色體系本身的設計：

| 維度 | 元素 | 花色 | 意義 |
|---|---|---|---|
| `action` | 火 | 權杖 | 行動、衝勁、推進 |
| `emotion` | 水 | 聖杯 | 情感、人際、感受 |
| `logic` | 風 | 寶劍 | 思維、判斷、溝通 |
| `material` | 土 | 錢幣 | 物質、金錢、實務 |

每張牌的維度向量 `dimensions`，各軸值域 `0 ~ 1`，代表「這張牌在該面向的著力程度」。

### 3.2 極性（polarity）

獨立於維度之外的單一數值，值域 `-1 ~ 1`，代表牌義的正負向。這是**唯一無法從現有屬性完整推導**的資訊，也正是 v1 決議 #1 當時擱置的「78 張極性表」。本版以推導值起步，允許逐張覆寫。

### 3.3 推導規則（零標註基礎值）

**小牌（數字牌）**
- 維度：該花色對應軸 = `1.0`，其餘 = `0`
- 極性：`clamp(數字極性 + 花色偏移, -1, 1)`

數字極性（沿用 `NUMBER_THEMES` 的語意）：

| 數字 | 主題 | 極性 |
|---|---|---|
| 1 | 開始 | +0.5 |
| 2 | 抉擇、平衡 | 0.0 |
| 3 | 成長、合作 | +0.5 |
| 4 | 穩定 | +0.3 |
| 5 | 衝突 | −0.6 |
| 6 | 和諧、回復 | +0.5 |
| 7 | 考驗、反思 | −0.3 |
| 8 | 推進、掌控 | +0.4 |
| 9 | 臨界、獨立 | −0.1 |
| 10 | 完成或過載 | +0.2 |

花色偏移（RWS 傳統上寶劍偏艱難）：權杖 `+0.05`、聖杯 `+0.05`、錢幣 `+0.05`、寶劍 `−0.25`

**宮廷牌**
- 維度：花色對應軸 = `1.0`
- 階級修正（影響強度與模式，不影響極性）：侍者 `0.6`、騎士 `0.9`、王后 `0.8`、國王 `1.0`
- 極性：`+0.2`（宮廷牌多為中性偏人物描述）

**大牌**
- 維度：金色黎明元素對應軸 = `1.0`（已有資料，零標註）
- 極性：見 3.3.1 的完整對照表

### 3.5 位置權重（`spreads.js` 新增 `weight`）

每個位置加一個 `weight`，同一牌陣內**總和為 1**。未定義時所有位置均分（手動選牌即走此路徑）。

| 牌陣 | 位置與權重 |
|---|---|
| 時間之流 | 過去 **0.20**、現在 **0.35**、未來 **0.45** |
| 直指核心 | 問題核心 0.30、障礙 0.20、對策 0.30、資源 0.20 |
| 指引之星 | 問題 0.10、過去影響 0.10、負面影響 0.15、現在 0.20、正面影響 0.15、未來 0.15、終局 0.15 |
| 自選牌（手動） | 平均分配 `1/n` |

**關於「未來」權重的評估結論（原草案 0.5，調整為 0.45）**

DI 回答的是「指向哪裡」，未來位置確實最相關，理應最重。但 0.5 代表單一張牌佔掉一半分數，抽到一張極端牌就會主導整個結果，穩健度太低。把現在從 0.30 提到 0.35、未來從 0.50 降到 0.45，未來仍是最重的位置，但過去＋現在（0.55）略高於未來，單張牌不會獨斷。

**已知限制（不在本版處理，列為後續優化）**

「障礙」與「負面影響」這類位置，本質上就預期抽到負面牌。目前所有位置一律以 `+1` 計入極性，所以障礙位抽到重度負面牌會拉低 DI（這是對的），但若抽到強正向牌（例如障礙位出現太陽），語意會變得曖昧。這類情況在實務上少見，本版先維持一致處理，不做位置別的符號反轉，避免規則過度複雜。

### 3.5.1 問題類型選單（新增需求）

目前領域只靠關鍵詞比對（規則 7），問法稍微不同就可能判錯，直接影響 DI。因此新增**明確的問題類型選擇**，讓使用者自己指定，避免權重算錯。

**前端**：問題輸入框下方加一個下拉選單，抽牌與選牌兩種模式共用。

| 選項 | 送出值 | 行為 |
|---|---|---|
| 自動判斷（預設） | 不送 `domain` | 走規則 7 關鍵詞比對；比對不到則用預設均等權重 |
| 工作 / 事業 | `work` | 直接採用該領域權重 |
| 財務 / 金錢 | `money` | 同上 |
| 感情 | `love` | 同上 |
| 人際 / 家庭 | `social` | 同上 |
| 學業 / 決策 | `study` | 同上 |
| 綜合 / 其他 | `general` | 強制使用均等權重（四軸各 0.25） |

**後端決定領域的優先序**：

1. 使用者明確指定的 `domain`（需在允許清單內，否則回 400）
2. 關鍵詞比對（規則 7）的結果
3. 都沒有 → `general`，四軸均等權重

此欄位要同時支援 `/api/readings/draw`、`/api/readings/manual`、`/api/readings/narrate` 三個端點。規則 7 的「問題對照」顯示也沿用同一個領域來源，兩邊不會各算各的。

**相容性**：`domain` 為選填，舊的請求不帶此欄位時行為與現在完全相同。

## 四、演算法

### 4.1 單張牌的領域投影值

對第 `i` 張牌：

```
d_i[k]      = dimensions_i[k] / Σ_k dimensions_i[k]        // 正規化成總和 1
relevance_i = Σ_k ( d_i[k] × domain[k] ) / max_k(domain[k]) // 相對吻合度
v_i         = polarity_i × relevance_i × orient_i × rank_i
```

**為什麼 relevance 要除以 `max(domain)`（施作時修正）**

若直接用 `Σ(d × domain)`，單一元素的牌在均等領域只會拿到 0.25，等於所有牌一律打四折，實測 DI 值域被壓縮到 ±25，±60 的「強烈」門檻永遠達不到。改成除以該領域最在意的那一軸後，「完全對題」的牌 relevance = 1，值域才展得開。修正後實測：全正向牌組 DI = 90、全負向 = −82、中性 = −8.5。

- 正規化後 `Σ d_i[k] = 1`、`domain[k] ≥ 0` → `Σ(d·domain) ≤ max(domain)` → `relevance_i ∈ [0,1]`，**仍由建構保證，不需夾擠**
- `polarity_i ∈ [-1,1]`
- `orient_i`：正位 `1.0`、逆位 `0.45`（**衰減，不翻轉**，符合規則 6）
- `rank_i`：宮廷階級修正，其餘為 `1.0`
- 因此 `v_i ∈ [-1, 1]`，**由建構上成立，不需夾擠**

### 4.2 指向分數（Direction Index, DI）

```
w_i = position_weight_i × card_base_weight_i        // 大牌 3／宮廷 2／數字 1
DI  = 100 × Σ(w_i × v_i) / Σ(w_i)
```

因 `v_i ∈ [-1,1]` 且 `w_i > 0`，加權平均必落在 `[-1,1]`，故 `DI ∈ [-100, 100]`。**無魔術常數、無 clamp**。

### 4.3 四軸能量（雷達圖用）

```
energy[k] = Σ( w_i × dimensions_i[k] × orient_i ) / Σ(w_i)        // ∈ [0,1]
```

注意此處**不乘極性**：雷達圖表達的是「力氣花在哪個面向」，不是好壞。好壞由 DI 與極性分項表達。

### 4.4 動能與阻力

```
momentum  = Σ( w_i × relevance_i × [正位] ) / Σ(w_i)      // 正位牌在該領域的推力
resistance = Σ( w_i × [逆位] ) / Σ(w_i)                   // 與規則 10 的 reversedWeightRatio 定義一致
```

**修正（2026-10-12）**：原本寫「`resistance` 與規則 10 的 `reversedWeightRatio` 採同一定義」，**這是錯的**。規則 11 的 `resistance` 多乘了牌陣位置權重，兩者在有位置權重的牌陣下會得到不同的值（實測 0.15 vs 0.25）。因為畫面上同時顯示兩個算法不同的「阻力」會互相矛盾，已改為**只在指向分析顯示一次**，規則 10 的「這件事有多大」不再提阻力（欄位保留供相容）。

### 4.5 明朗度（confidence）

分數的可信程度，用來在畫面上提醒「這組牌訊號分散，別過度解讀」。

```
confidence = 1
           − 0.30 × (元素未知的牌權重佔比)
           − 0.25 × (四軸能量的分散程度，用正規化熵)
           − 0.15 × (矛盾點數量 / 牌數，上限 1)
           − 0.10 × (問題未命中任何領域 ? 1 : 0)
```
結果 `clamp(0, 1)`。四項係數放 `ruleConfig.js`，可調。

### 4.6 指向判定（本版的核心輸出）

將 DI 與 confidence 轉成**語意分級**，畫面以分級為主、數字為輔：

| DI 區間 | 指向 | 說明 |
|---|---|---|
| ≥ +60 | 明顯順利 | 牌面明確支持 |
| +20 ~ +60 | 偏順利 | 大致有利，有條件 |
| −20 ~ +20 | 好壞參半 | 訊號互相抵銷 |
| −60 ~ −20 | 偏不順 | 阻力明顯 |
| ≤ −60 | 明顯不順 | 牌面明確不支持 |

`confidence < 0.5` 時，分級後方標註「訊號分散，僅供參考」。

## 六、視覺化（前端）

「指向分析」區塊放在**「查看判斷依據」摺疊區內**，排在最上方（組合分析之前）。

1. **指向儀表**：一條 −100 ～ +100 的水平軸，指針落在 DI 的位置；**只顯示分級文字（例如「偏正向」）與指針位置，不顯示 DI 數字**
2. **四軸雷達圖**：行動／情感／思維／物質的 `energy`，用 Chart.js 繪製
3. **動能 vs 阻力**：兩條對比傾向條，沿用規則 10 既有的三格樣式
4. **貢獻排行**：依 `|share|` 排序，正向綠、負向紅，標出哪張牌推高／拉低
5. **明朗度**：低於 0.5 時顯示「訊號分散，僅供參考」

樣式沿用深色玻璃質感與現有 Tailwind class。

### 圖表套件（已核准新增）

| 項目 | 決定 |
|---|---|
| 套件 | `chart.js` + `vue-chartjs` |
| 理由 | 雷達圖為內建型別、TypeScript 型別完整、維護活躍；體積（gzip 約 60KB）遠小於 ECharts |
| 載入方式 | 只註冊 `RadarController`、`RadialLinearScale`、`PointElement`、`LineElement`、`Filler`，其餘不註冊以利 tree-shaking |
| 不用於 | 指向儀表與傾向條。這兩者是單純的水平軸與色塊，用 Tailwind 的 div 即可，套圖表反而更重更難調樣式 |

### 誠實呈現原則

- **不顯示 DI 數字**，只給分級與儀表指針位置，避免「78.5 分」這種假精確感
- `confidence` 低於 0.5 時必須顯示提醒
- 說明文字明確寫出「這是依規則計算的傾向，不是預測」
- 雷達圖的軸標示為「力氣花在哪個面向」，不標示好壞
