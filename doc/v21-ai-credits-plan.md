# v21　AI 點數收費：綠界金流、點數包、各 AI 功能點數

建立日期：2026-11-11
狀態：規劃中，**暫不實作**（2026-11-11 使用者決定先寫計畫書，等申請資格、發票與定價確認後再開工）

## 一、目標

現在 AI 功能只開放給管理者與被開通 `aiAccess` 的會員，每次呼叫 OpenRouter 的費用都由站方吸收。這一版讓一般會員可以**買點數、用點數換 AI 功能**：

1. **點數包**：會員用綠界付款買點數，付款成功後自動加點。
2. **每個 AI 功能各自標價**，使用時從餘額扣點；AI 沒產生出內容就退回。
3. **流水帳**：每一筆加點、扣點、退點都有紀錄，會員看得到自己的，管理者看得到全部，並能手動補點。

### 不做的事

- **不做訂閱制、月費**：只賣一次性的點數包。
- **不在網站內輸入卡號**：一律跳到綠界的付款頁（綠界的 AIO 全方位金流）；站內刷卡（TapPay、綠界站內付）不在本版。
- **不做點數轉讓、贈送他人、兌換現金**。
- **不做優惠碼、首購優惠、推薦獎勵**。
- **不做分期付款與國外信用卡**：綠界個人會員通常不能開。
- **不改 AI 本身**：模型、提示詞、輸出格式都維持現狀，這一版只加「能不能用、扣多少點」。
- **非 AI 功能維持免費**：抽牌、規則引擎的組合分析、股市資料、新聞列表都不扣點。

## 二、規格

### 2.1 金流：綠界（ECPay）

- 使用 AIO 全方位金流：後端組好訂單參數與 `CheckMacValue`，前端用表單把資料送到綠界的付款頁。
- 付款方式：信用卡為主；ATM 轉帳與超商代碼是「稍後才付款」，開放與否見 2.8 待決事項。
- **加點只依據綠界的付款結果通知（`ReturnURL`）**。使用者付完錢被導回網站的頁面（`OrderResultURL`）只負責顯示結果，不加點：使用者可能直接關掉頁面，成功頁的網址也可能被偽造。
- 收到通知時：
  1. 用綠界的 HashKey／HashIV 重新計算 `CheckMacValue`，和通知裡的值比對，不一致就丟掉。
  2. 確認 `RtnCode` 是付款成功、金額和訂單一致。
  3. 以訂單編號（`MerchantTradeNo`）判斷是否處理過；綠界會重送通知，同一筆只能加一次點。
  4. 回覆 `1|OK`；沒回的話綠界會一直重送。
- 簽章用 Node 內建的 `crypto` 計算，**不加套件**。
- 環境變數：`ECPAY_MERCHANT_ID`、`ECPAY_HASH_KEY`、`ECPAY_HASH_IV`、`ECPAY_ENV`（`stage` 測試／`prod` 正式）。開發一律先用綠界公開的測試商店。
- 付款結果通知網址指向 Cloud Run 上的後端；本機測試需要用 ngrok 之類的工具，讓外網能連進本機。

### 2.2 點數包

定義在後端的設定檔（例如 `src/data/creditPacks.js`）。前端只送點數包的 id，**金額與點數一律以後端定義為準**。

| id | 點數 | 售價（暫定） | 備註 |
|---|---|---|---|
| p50 | 50 | 待定 | 入門 |
| p120 | 120 | 待定 | 約多送 20% |
| p300 | 300 | 待定 | 約多送 50% |

售價要等 2.3 的實際成本算出來再決定，原則是「最便宜的包也要能蓋過 OpenRouter 成本＋綠界手續費（約 2～3%）」。

### 2.3 各 AI 功能的點數（暫定）

目前呼叫 AI 的地方：

| 功能 | API | 現有每日上限 | 暫定點數 |
|---|---|---|---|
| 塔羅 AI 解讀（一般領域） | `POST /api/readings/narrate` | 無 | 1 |
| 塔羅 AI 解讀（股市諮詢領域） | `POST /api/readings/narrate`（`domain` 為股市） | 無 | 2 |
| 個股 AI 深度分析 | `POST /api/market/stock/:code/analysis/ai` 等 | 20 次（`marketAnalysis.js` 的 `DAILY_LIMIT`） | 3 |
| 財經新聞 AI 影響分析 | `POST /api/market/finance-news/analysis` | 10 次（`financeNews.js` 的 `DAILY_LIMIT`） | 3 |

- 點數要依實際成本校正：開工前先從 OpenRouter 的用量紀錄算出每種功能**平均一次花多少錢**，再回填這張表與 2.2 的售價。
- 每種功能的點數放在後端設定檔，前端從 API 讀取後顯示「需 N 點」，前端不寫死。
- 現有的每日上限**保留**，用來防止濫用；有點數也不能超過每日上限。

### 2.4 扣點與退點

- **先扣點，再呼叫 AI**。扣點必須用一次完成的資料庫更新：條件是「餘額 ≥ 點數」，同時扣掉。如果先查餘額、再另外扣，使用者連按兩次時可能被扣成負數。
- 點數不足：回 **402**，訊息寫「點數不足，這次需要 N 點，目前剩 X 點」，前端照原文顯示。
- **退點**：AI 端出錯、或還沒產生任何內容就失敗時，退回點數。
- **不退點**：AI 已經開始產生內容後被使用者按停止。這和現有 `MarketAiUsage` 的規則一致（開始產生就算一次），避免用「開始後馬上停止」來白用。
- 管理者不扣點；`aiAccess` 會員的處理見 2.8 待決事項。

### 2.5 資料結構

- **`User` 新增 `credits`**（數字，預設 0）：餘額，查詢用。
- **新增 `CreditTransaction`**（流水帳，對帳依據）：
  - `user`、`delta`（+120／-3）、`balanceAfter`
  - `type`：`purchase` 購買、`spend` 使用、`refund` 退點、`admin_grant` 管理者補點、`payment_refund` 金流退款扣回
  - `kind`：扣點時記錄用在哪個 AI 功能（`narrate`／`stock`／`news`）
  - `ref`：訂單編號、解讀紀錄或分析紀錄的 id
  - 購買那筆的訂單編號設為**不可重複**，資料庫層級擋住重複加點。
- **新增 `CreditOrder`**（訂單）：`merchantTradeNo`、`user`、`packId`、`amount`、`points`、`status`（`pending`／`paid`／`failed`）、綠界回傳的交易編號、付款方式、付款時間。建立付款時先存一筆 `pending`，收到通知才改成 `paid` 並加點。

### 2.6 API（暫定）

| API | 說明 |
|---|---|
| `GET /api/billing/packs` | 列出點數包與各 AI 功能的點數 |
| `POST /api/billing/checkout` | 送 `packId`，回傳要送給綠界的表單參數（已含 `CheckMacValue`） |
| `POST /api/billing/ecpay/notify` | 綠界付款結果通知（不需登入，靠 `CheckMacValue` 驗證） |
| `GET /api/billing/orders/:no` | 查一筆訂單的狀態，給成功頁輪詢用 |
| `GET /api/billing/transactions` | 我的點數流水帳 |
| `GET /api/auth/me` | 回傳多一個 `credits` 欄位 |
| `PATCH /api/admin/users/:id/credits` | 管理者補點或扣點（寫進 `AdminLog`） |

### 2.7 前端

- `types.ts`：使用者加 `credits?`，新增點數包、流水帳的型別，都設為可選（線上後端可能還是舊版）。
- 購買頁：列出點數包，按下後把表單送到綠界的付款頁。
- 付款結果頁：不自己加點，用訂單狀態 API 輪詢幾次，等後端收到綠界的通知；等太久就顯示「付款處理中，稍後到點數紀錄查看」。
- 每個 AI 按鈕旁顯示「需 N 點，剩 X 點」；點數不足時改成引導去購買。收到 402 時把後端的訊息照原文顯示。
- 「我的點數」頁：餘額與流水帳。
- 管理者會員頁：顯示每位會員的餘額，可手動補點。

### 2.8 待決事項（開工前要確認）

1. **申請身分與發票**：綠界個人會員每 30 天收款上限 20 萬元，商務會員 50 萬元。開統一發票通常需要營業登記；用個人身分可能只能收款、不能開發票。要確認是否先登記行號，再升級為商務會員。
2. **`aiAccess` 會員怎麼處理**：維持完全免費（白名單），或改成每月送固定點數？
3. **點數有沒有使用期限**：點數屬於預付型的商品，設期限可能牽涉消費者保護的規定。暫定**不設期限**。
4. **是否開放 ATM 轉帳、超商代碼**：這兩種要等使用者實際去付款才會收到成功通知，訂單會停在 `pending` 一段時間，需要訂單過期的處理。暫定**只開信用卡**。
5. **付款後退款**：綠界的退款要在後台或用另一支 API 處理。退款時把當初加的點數扣回來；如果點數已經用掉，餘額可能變負數，負數時不能使用 AI。是否接受這個做法待確認。
6. **定價**：2.2 的售價、2.3 的點數都待實際成本算出後回填。
