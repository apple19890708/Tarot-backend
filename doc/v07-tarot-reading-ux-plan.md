## 二、牌卡翻面（需求 1）

### 現況

位置意義顯示在排列圖**下方**一個 `<p>`，靠 `activeKey` 切換（`SpreadLayout.vue:105-117`）。滑過或點選才顯示，視線要在牌和說明之間來回跑。

### 改為

點牌卡本身，卡片**翻到背面**顯示該位置代表什麼，下方那個 `<p>` 移除。

```
正面                    背面
┌──────┐               ┌──────┐
│      │               │ 現況 │
│ 牌圖 │   ── 點擊 ──► │      │
│      │               │事情目前│
└──────┘               │的核心 │
 寶劍八                │ 狀態 │
 正位                  └──────┘
```

### 實作要點

- 3D 翻轉用 Tailwind 任意值：外層 `[transform-style:preserve-3d] [perspective:600px]`，正反面各 `[backface-visibility:hidden]`，背面多一個 `[transform:rotateY(180deg)]`。沿用既有玻璃質感，**不另外寫 CSS 檔**。
- **逆位的 `rotate-180` 只加在正面的 `<img>`**（現在就是這樣），所以背面不會跟著上下顛倒，不必額外處理。
- **取消 `@mouseenter` 自動切換**。現在滑過就換 `activeKey`，改成翻面後會變成滑過就亂翻。hover 只保留邊框高亮，翻面一律靠點擊。
- 翻面是切換，再點一次翻回來。加一顆「全部翻面」按鈕，一次看完所有位置。
- 無障礙：`aria-pressed` 標示翻面狀態，`aria-label` 保持「位置名稱：位置說明」。

### 卡背文字：用 RWD 調整字級

實測四個牌陣的 `prompt` 長度：**最短 4 字（「現況總覽」）、最長 17 字（「如果照目前方向前進，局勢會如何發展」）**。

**卡片尺寸不動**（維持 `w-16` / `sm:w-20`，塞爾特十字在手機本來就橫向捲動，加寬只會更難滑），改用斷點調整字級，讓同一段文字在各尺寸下都剛好填滿卡背。

| 斷點 | 卡片寬 | 位置名稱 | 位置說明 | 行高 | 17 字佔 |
|---|---|---|---|---|---|
| 預設（手機） | w-16 / 64px | `text-[10px]` | `text-[9px]` | `leading-[1.15]` | 4 行 ≈ 42px |
| `sm:`（≥640px） | w-20 / 80px | `text-[11px]` | `text-[10px]` | `leading-tight` | 3 行 ≈ 36px |
| `lg:`（≥1024px） | w-20 / 80px | `text-xs` | `text-[11px]` | `leading-snug` | 3 行 ≈ 42px |

卡背高度 96px（手機）／120px，扣掉 `p-1.5` 內距與位置名稱一行，最長的 17 字在任一斷點都留有餘裕。

寫法沿用既有的 Tailwind 斷點前綴，不另外寫 CSS：

```html
<span class="text-[10px] leading-[1.15] sm:text-[11px] sm:leading-tight lg:text-xs lg:leading-snug">
```

兩個細節：

- 位置說明加 `break-words`，避免長詞把卡背撐破。
- 卡背用 `flex flex-col justify-center` 垂直置中，短的「現況總覽」才不會黏在上緣。

└─────────────┘     └─────────────┘      └─────────────┘

三種抽牌方式都在步驟 2，前面照樣先選問題與牌陣：

| 方式 | 做什麼 | 對應現況 |
|---|---|---|
| 自動抽牌 | 系統抽 N 張並決定正逆 | 現有 `/draw`，不變 |

### 手動抽牌：扇形牌堆

這是需求裡講的「隨機亂數打散讓使用者選」，和「輸入已抽到的」是兩回事 —— **使用者點的時候看不到是什麼牌**，牌面朝下，點了才翻開。

版面依參考圖，78 張牌背排成**扇形弧線**，滑過的那張**稍微浮起**：

```
步驟 2・手動抽牌（牌陣需要 6 張，已選 2 張）

                    ╭─╮              ← 滑過的牌上浮
         ╭─╮ ╭─╮ ╭─╮│ │╭─╮ ╭─╮ ╭─╮
    ╭─╮  │ │ │ │ │ ││ ││ │ │ │ │ │  ╭─╮
  ╭─╮ │  │ │ │ │ │ ││ ││ │ │ │ │ │  │ │ ╭─╮
 ╱  └─┴──┴─┴─┴─┴─┴─┴┴─┴┴─┴─┴─┴─┴─┴──┴─┴──╲     78 張，背面，亂序

  已放入牌陣：
  ①現況 🂠   ②阻礙 🂠   ③根基 ·   ④過去 ·   ⑤意識 ·   ⑥近未來 ·
```

#### 扇形與浮起的實作

| 項目 | 做法 |
|---|---|
| 排列 | 容器 `relative`，每張 `absolute` 並以 `transform: rotate(θ) translateY(R)` 定位，`θ` 從 `-maxAngle` 線性分到 `+maxAngle`，`R` 為弧半徑 |
| 旋轉原點 | `origin-bottom`，讓每張牌以扇柄為軸旋轉 |
| 疊序 | `z-index` 依序遞增，hover 時拉到最上層 |
| 浮起 | hover／focus 時在既有 `rotate` 後接 `translateY(-12px)` 並加 `scale(1.04)`，`transition-transform duration-200 ease-out` |
| 已選 | `opacity-40` 並移除 hover 效果，不可再點 |

兩個細節要注意：

- **浮起不能覆寫旋轉**。`transform` 是單一屬性，hover 時必須輸出「原本的 rotate ＋ 新的 translateY」完整字串，只寫 `translateY` 會讓牌瞬間轉正。用 CSS 變數（`--deg` 存角度）寫成 `transform: rotate(var(--deg)) translateY(...)` 最乾淨。
- **點擊區域會互相遮擋**。扇形牌片大幅重疊，`z-index` 高的會吃掉下層的點擊。hover 浮起剛好同時解決這件事 —— 指標所在的牌被拉到最上層，點到的一定是看到浮起的那張。

#### 尺寸與 RWD

| 斷點 | 展開角度 | 弧半徑 | 牌寬 |
|---|---|---|---|
| 手機 | ±55° | 180px | 40px |
| `sm:` | ±65° | 260px | 52px |
| `lg:` | ±75° | 340px | 64px |

78 張分在這個角度範圍內，相鄰間距約 1.4°–1.9°，重疊很重但扇形本來就是這樣，露出的邊緣足以點選。手機若覺得太密，可改成**上下兩道弧**各 39 張 —— 這點做的時候看實機再決定。

觸控沒有 hover，手機改成**點一下先浮起預覽、再點一次才確認選取**，避免誤觸。

#### 其餘機制

1. 進入步驟 2 時向 `/api/cards` 取回 78 張，前端用 Fisher–Yates 洗牌，**並為每張獨立亂數決定正／逆位**。這份順序與正逆位在這一輪固定住，重新整理才重洗。
2. 全部以**牌背**呈現，不顯示牌名也不顯示正逆。
3. 使用者點第 k 張 → 直接填進牌陣第 k 個位置，排列圖上即時翻開。點選順序就是位置順序，不需要拖曳。
4. 已選的牌從牌堆淡出、不可重複點（後端的重複檢查維持，當第二道防線）。
5. 選滿 N 張才能進步驟 3；中途可「收回最後一張」。

要注意的：

- **正逆位必須在洗牌時就決定，不能等使用者選完才抽**。否則「手動」只是換個介面的自動抽牌，點哪一張都沒差別。
- 不要做一張張發牌的動畫（78 張的進場動畫等待時間太長）。扇形直接成形，只保留 hover 浮起這一個互動動畫。
- 78 張 `absolute` 卡片只有 `transform` 和 `opacity` 在變，都走 GPU 合成，效能沒問題；但**不要對 `box-shadow` 做 transition**，那會觸發重繪。要陰影變化就用兩層疊加、改 `opacity`。
- 送出時用的還是 `/api/readings/manual`，body 形狀不變（`cards: [{ id, orientation }]` 依點選順序），只是多帶一個 `spreadKey`。**所以這個新互動不需要新端點。**
- 牌庫實際是 **78 張**（22 大牌＋56 小牌，已確認資料庫筆數），需求裡寫的 72 應是筆誤。

## 四、量化敘述自相矛盾（需求 3）

### 問題

> 正位與逆位各半，卻說「逆位的牌佔了不少」

### 根因

`analysisFormatter.js:341-347`：

```js
} else if (reversed.length / entries.length < 0.5) {
  lines.push('逆位的牌雖然不多，影響力卻不小，推進時會卡。')
} else {
  lines.push('逆位的牌佔了不少，推進時會卡。')   // ← 剛好各半會掉進這裡
}
```

`< 0.5` 為假時一律走 else，所以**剛好各半**（2 正 2 逆）被講成「佔了不少」，和畫面上的張數對不起來。

### 改為

| 逆位張數比 | 文字 |
|---|---|
| 只有 1 張 | 「只有 ○○ 是逆位，但它影響力夠大，推進時會卡。」（現狀，保留） |
| < 0.5 | 「逆位的牌雖然不多，影響力卻不小，推進時會卡。」（現狀，保留） |
| **= 0.5** | **「正逆各半，但逆位那半影響力更重，推進時會卡。」**（新增） |
| > 0.5 | 「逆位的牌過半，推進時會卡。」（措辭改明確，不用「不少」） |

### 同一段：正位卻說「拖」（已確認要做）

「其中**現況的寶劍八正位**拖得最明顯」語意沒錯（寶劍八本身偏負面，正位照樣拖），但「正位」緊接「拖」容易被誤讀成矛盾。

在 `top.share < 0` 且該牌為**正位**時補一句說明來源：

> 其中現況的寶劍八拖得最明顯（牌義本身就偏滯）。

逆位的牌拖不必補註，因為「逆位」本身已經解釋了原因。

## 五、數字階段改按牌陣順序（需求 4）

### 現況輸出

```
有數字的牌分布在：起步期 2 張、考驗與臨界期 1 張。以起步期為主。從起步期往考驗與臨界期推進。
```

講的是**分布**（幾張落在哪一期），而不是**走到哪個階段**。而且走向只比第一張和最後一張，中間的起伏看不到。

### 改為

依牌陣順序走一遍：

```
依牌陣順序：現況 起步期（2）→ 阻礙 考驗與臨界期（8）→ 結果 發展與穩定期（5）。
一開始衝到臨界，最後退回發展期穩住，中間卡了一關。
錢幣國王是宮廷牌，不計入數字。
```

### 資料結構

`analyzeNumberStage` 回傳值**新增**欄位，原有的 `stages` / `dominant` / `trend` / `evidence` 全部保留（測試 `combinationRules.test.js:273-284` 斷言的是這幾個，不能動）：

```js
{
  stages, dominant, trend, evidence,        // 既有，不變
  sequence: [                               // 新增：依牌陣順序
    { index: 0, number: 2, stage: 'start' },
    { index: 1, number: 8, stage: 'trial' },
    { index: 2, number: 5, stage: 'develop' },
  ],
  shape: 'peak',                            // 新增：整條路徑的形狀
  skipped: [3],                             // 新增：宮廷牌／無數字牌的 index
}
```

`shape` 判定（看相鄰 `order` 差值的序列）：

| shape | 條件 | 說法 |
|---|---|---|
| `flat` | 全部同階段 | 「一路停在○○，沒有往前也沒有退。」 |
| `rising` | 每步不降，且末 > 首 | 「從○○一路推到○○。」 |
| `falling` | 每步不升，且末 < 首 | 「從○○一路退回○○，像要回頭重整。」 |
| `peak` | 中間有高點，頭尾都低於它 | 「中段衝到○○，最後收在○○。」 |
| `dip` | 中間有低點，頭尾都高於它 | 「中間掉到○○，後面又拉回來。」 |
| `zigzag` | 其他 | 「階段起伏不定，節奏不穩。」 |

### 相容性

- 只有 1 張有數字的牌：`sequence` 長度 1，`shape = 'flat'`，文字只講落點不講走向。
- 全是宮廷牌：維持現狀回傳 `null`。
- 手動選牌無牌陣：位置名稱改用「第 1 張 / 第 2 張」。
- **分布句全部刪除**（已確認）。「有數字的牌分布在：起步期 2 張、考驗與臨界期 1 張」這類句子不再輸出，順序句取代它。`stages` 欄位仍保留在回傳值裡（測試有斷言，且 `dominant` 要靠它算），只是不再寫成文字。
- `dominant` 也不再單獨成句（「以起步期為主」）。階段集中與否，從順序句本身就看得出來。

## 六、宮廷牌一律說明影響力（需求 5）

### 現況輸出

```
錢幣國王（正位）：問題未涉及他人，視為性格或行動方式。
```

只講「代表誰」，沒講它在這組牌裡有多重。

### 改為

**不論代表誰，都先說影響力，再說角色。**

```
錢幣國王正位．現況：國王是宮廷裡份量最重的階級，又落在權重最高的位置，
這組牌約三成的影響力集中在它身上。問題沒提到其他人，把它當成你自己的姿態與做事方式。
```

三個資訊來源都已經有，不需要新規則：

| 資訊 | 來源 |
|---|---|
| 階級強度 | `COURT_RANK_INTENSITY`（page 0.6／knight 0.9／queen 0.8／king 1.0） |
| 位置權重 | `quant.contributions` 裡該 index 的 `weight` |
| 影響力佔比 | `quant.contributions` 裡該 index 的 `Math.abs(share)` |

**實作注意：`contributions` 是依 `|share|` 排序過的陣列，不是依 index 排列**（`quantRules.js:119`）。要用 `contributions.find(c => c.index === court.index)`，不可以寫 `contributions[court.index]`。

### 多張與零張

| 情況 | 處理 |
|---|---|
| 多張宮廷牌 | 依影響力排序，最重的那張講完整，其餘各一句；若階級相同再比位置權重 |
| 沒有宮廷牌 | 補一句「這組牌沒有宮廷牌，人的因素不是重點，關鍵在事情本身怎麼走。」 |

## 七、矛盾與不明朗改寫（需求 6）

### 問題

太抽象，因為句子在講**系統概念**（元素、焦點牌、主導花色），沒落到「實際上會怎樣」，也沒點名是哪個位置。

### 改寫對照

| 型態 | 現在 | 改為 |
|---|---|---|
| `enhanceWithBlocked` | 「寶劍八（正位）與聖杯二（逆位）元素互相增強，但其中一張是逆位（受阻），增強的效果未必能完全發揮。」 | 「**現況**的寶劍八和**阻礙**的聖杯二本來能互相幫上忙，但聖杯二是逆位，這份助力現在使不出來。」 |
| `focusOpposesDominantSuit` | 「焦點牌寶劍八（正位）的元素與主導花色錢幣（物質）對立，主題與主導領域之間存在拉扯。」 | 「你最在意的是**現況**那張寶劍八，但整組牌的重心壓在錢幣（物質）上。想的和實際要處理的不是同一件事，容易顧此失彼。」 |
| `courtRoleWithoutQuestion` | 「未提供問題，錢幣國王（正位）暫時視為性格或行動方式，也可能代表某位人物。」 | **維持現狀，不改**（已確認） |
| `unknownElement` | 「○○無法判定元素，未納入元素分析。」 | **維持現狀，不改**（已確認） |

只改上面兩種「矛盾」，兩種「不明朗」照舊。

三條原則：

1. **點名位置**（現況／阻礙／結果），不要只講牌名。
2. **去術語**：「元素互相增強」→「能互相幫上忙」；「主導花色」保留但要接白話解釋。
3. **講後果**，不要只講狀態：「未必能完全發揮」→「這份助力現在使不出來」。

### 禁用詞：「打折」

「打了折扣」「打個折」這類說法不再使用。規則引擎目前有兩處：

| 位置 | 現在 | 改為 |
|---|---|---|
| `analysisFormatter.js:115` | 「不過○○是逆位，這股作用目前**打了折扣**」 | 「不過○○是逆位，這股作用現在**使不出全力**」 |
| `analysisFormatter.js:333` | 「其中○○影響力最大，但它是逆位，**力道打了折扣**，推進時會卡。」 | 「其中○○影響力最大，但它是逆位，**力道出不來**，推進時會卡。」 |

**辭典裡的 44 行也一併清掉（已確認）。** 分布在 `pairs/money/major.js` 20、`study/major.js` 6、`love/major.js` 5、`social/major.js` 5、`buildCuratedPairs.js`＋`curatedPairs.js` 各 3、`seedPairsManual.js` 2，匯出檔共 66 處。

那是「A 與 B 都打折」的用法（兩邊都減弱），與要禁的「打個折」（保留懷疑）語意不同，但既然「打折」整個不用，就一起換掉。改法：依前後文選「使不上力／不到位／都弱了／都減了幾分」，不要全部套同一個詞，否則辭典會出現大量重複句型。

流程：改來源檔 → `node scripts/pairs/seed.js <domain>` 重新 seed 受影響的領域 → `npm run pairs:export` 重出 `牌與牌關係.md`。

## 八、guidance 重寫（需求 7）

### 根因（比看起來嚴重）

`readingService.js:81`：

```js
.map((entry, index) => `${positionLabelOf(entry.position, index)}重點是${entry.interpretation}`)
```

而 `interpretation` 本身（`readingService.js:33`）已經是：

```js
`${label}出現${card.nameZh}${orientationLabel(orientation)}，${opening}`
```

兩邊都加了位置名稱，所以實際輸出是：

> **現況重點是現況出現**寶劍八正位，…… **阻礙重點是阻礙出現**聖杯二逆位，……

位置名稱被印了兩次，「重點是」「出現」兩個贅詞疊在一起。而且是把每張牌的開場句用空白串起來，這是**列舉，不是總結**。

### 改為三句式總結

不再逐張列舉（每張牌下面本來就有完整牌義，重複沒意義），改成抓最強的三個訊號：

| 句 | 內容 | 資料來源 |
|---|---|---|
| 1 份量 | 「這組牌的份量集中在**現況**的寶劍八正位。」 | `quant.contributions[0]` |
| 2 張力 | 「**資源**的錢幣九推得動，**阻礙**的聖杯二逆位拖住。」 | `contributions` 最大正值 ／ 最大負值 |
| 3 落點 | 「照目前走向，**結果**會停在世界逆位。」 | 牌陣最後一個位置，或 `結果`／`終局`／`未來` |

邊界情況：

- 推力與阻力是同一張牌 → 第 2 句改成「○○同時是推力也是變數」。
- 只有推力沒有阻力（或反之）→ 第 2 句只講有的那半。
- 手動選牌無牌陣 → 位置名稱換成「第 N 張」，第 3 句改用整體指向。
- 只有 1 張牌 → 只留第 1 句。

測試 `combinationRules.test.js:113` 只斷言 `reading.guidance` 為真值，不會因為改寫而失敗。

## 九、牌對關係加位置小標題（需求 8）

### 現況

`ReadingAnalysisPanel.vue:166-212` 顯示兩張牌的圖、牌名、正逆位、關係標籤，但**沒有位置**。換成新辭典文字之後更需要知道是哪兩個位置在比。

### 改為

每組上面加一行小標題：

```
現況 寶劍八 正位 ── 對應 ── 阻礙 聖杯二 逆位              [中性]
────────────────────────────────────────────────
（辭典文字）
```

### 資料

- **位置名稱不需要後端改**：`reading.cards[pair.from].position.label` 前端本來就拿得到。
- **關係型態要補型別**：後端 `analysisFormatter.js:379` 已經輸出 `kindLabel`（順承／橫跨／對照／表裡／對策／投射／整體），但 `types.ts:112-120` 的 `AnalysisPair` 沒有這個欄位，前端讀不到。依專案慣例**設為可選**（`kindLabel?: string`），因為 Render 上的後端可能還是舊版。
- `relation`（增強／中性／衝突）維持現在的彩色標籤，放在右側，不要和 `kindLabel` 混在一起 —— 兩者是不同維度。
- 手動選牌無牌陣時 `position` 為 `null`，退回「第 1 張 / 第 2 張」。
